Key findings

  1. The decisive fix was not the loss but the data. Masking the map-projection no-data wedges (v3) removed a nuisance mode that had made every v1/v2 flag a border crop. It turned a bimodal score distribution into a unimodal one with a genuine tail.
  2. The flagged set contains clear non-Martian content (an aerial photograph of the Pentagon, perfectly periodic grids), recognisable in Phase 3 by diffuse whole-frame reconstruction error. It also contains rare genuine terrain (north-polar layered deposits, fresh deep craters), which the metadata join (2.3) identifies as a terrain class concentrated in two polar observations.
  3. The spatial bottleneck (v4) was tried and rejected, because its coordinates encoded local brightness.
  4. Limitations: small local sensor defects are missed by latent-space scoring (the residual catches two of three), and recall for terrestrial content is incomplete (sample_05508).

0. Data and sanity pass

Sanity-pass findings

  • 10,422 single-channel 227×227 JPEG crops from 172 source observations; every crop maps to exactly one source_image_id and every id has metadata (checked with assert).
  • Pixel values span the full 0-255 range; we rescale by 1/255 to [0, 1] and use a sigmoid decoder output.
  • ≈20 % of crops contain a solid-black no-data wedge (the map-projected edge of the HiRISE strip). These are normal data, but they are the highest-contrast edges in the whole dataset, which matters for both the reconstruction loss and the anomaly detector (see changelog).
  • Very bright crops (frost / dust) exist and are genuine terrain, so a brightness heuristic cannot separate anomalies - consistent with the organisers' warning.

0.2 No-data (map-projection) masking - introduced in v3

v1 and v2 showed that the black map-projection wedges, which are normal data, dominated both the reconstruction loss and the latent space (see changelog). From v3 on, each crop gets a no-data mask. A pixel is masked if it belongs to a near-black (≤ 5) region that

  • survives a 5×5 morphological opening, so thin dark lines are not masked. A dead sensor column or a black streak could itself be an injected anomaly, and hiding it would be wrong.
  • touches the crop border, because strip edges enter from outside the crop.
  • covers at least 0.5 % of the crop.

The mask is dilated by 2 px to cover JPEG ringing along the wedge edge. Masked pixels are filled with the median of the crop's valid pixels, which gives a flat, texture-free region with no razor-sharp edge. They are also excluded from the loss and from every reconstruction-error metric and heatmap. The filled image, not the original, is what the v3 encoder sees.

Phase 1 - Deep Latent Compression

1.1 Architecture design

Design. A convolutional autoencoder written from scratch in PyTorch (no pretrained weights, no transfer learning).

  • Encoder: five stride-2 3×3 convolutions (32→64→128→256→256 channels), BatchNorm + LeakyReLU. 227 → 114 → 57 → 29 → 15 → 8. Five halvings are the minimum that brings the map to 8×8, so the deepest units have a receptive field covering a large part of the crop (whole craters, dune trains) before the bottleneck.
  • Bottleneck (final model, v3): flatten (256×8×8 = 16,384) → Linear → fixed-length 1-D latent vector of 256 floats (the Phase 2 input). The global linear layer lets every latent coordinate combine evidence from the whole crop, so the code describes what kind of scene this is (terrain type, texture class, relief).
  • Alternative tried and rejected (v4): a spatial bottleneck, a 1×1 convolution to an 8×8 grid × 4 channels flattened to the same 256-d vector. The aim was to keep small local defects visible, but each coordinate then mostly encoded local brightness, so the Isolation Forest isolated very bright or dark scenes instead of anomalies (see changelog). We therefore kept the global code.
  • Decoder: mirror image: Linear (v4: 1×1 conv) back to the 8×8×256 map → five ×2 transposed-conv stages to 256×256, centre-crop to 227×227, sigmoid. Cropping (rather than odd output-padding) keeps every stage a clean ×2.
  • Stride-2 convolutions replace pooling so the network learns its own downsampling.
  • The bottleneck type, latent size, loss and no-data handling are configurable because they change across v1 → v4 (CONFIGS).

The latent size trades reconstruction fidelity (a larger code keeps more detail) against outlier separability. An Isolation Forest splits on randomly chosen coordinates. If many latent dimensions carry redundant or near-constant information, most random splits are wasted and the isolation depth of true outliers gets diluted. We trained the final configuration with d ∈ {64, 128, 256, 512} (short schedule) and measured three things:

  • held-out SSIM (fidelity)
  • the number of principal components needed for 90 % of latent variance (how much of the code is used)
  • a label-free separability proxy: the tail ratio (99.9th-percentile Novelty Score − median) / MAD. This measures how far the most isolated crops sit from the bulk, in robust units.

Choice: d = 256. The sweep uses a short 12-epoch schedule and a single seed, so its flagged counts are not comparable with the fully trained model and are shown only for completeness. The differences are indicative, not conclusive.

  • Fidelity saturates. Held-out SSIM is 0.682 (64), 0.678 (128), 0.692 (256) and 0.696 (512). Doubling from 256 to 512 buys only +0.004.
  • Effective dimensionality grows sub-linearly. 30, 8, 85 and 109 principal components hold 90 % of the latent variance. Going to 512 adds 256 coordinates but only about 24 effective directions. The rest are redundant, and redundant coordinates dilute an Isolation Forest, whose splits pick a coordinate uniformly at random.
  • Separability peaks at 256. The tail ratio is 10.9, 9.5, 11.0 and 10.5. The correlation with the no-data fraction (the nuisance removed in v3) creeps up with size (0.03 → 0.08), because a bigger code has room to re-encode fill geometry.
  • d = 128 is an outlier. 90 % of its variance sits in only 8 components, a partial collapse under the short schedule, and it has the weakest tail.

So 256 is the knee of the trade-off: the smallest code at which reconstruction fidelity is essentially saturated and the separability proxy is at its maximum.

1.2 Loss function design

Loss design. v1 used pure MSE. MSE is minimised by the conditional mean, so when fine texture (dune ripples, crater rims, polygonal ground) is uncertain the decoder outputs a blurred average. The v1 reconstructions show this clearly (Fig 1.2). From v2 on, the objective is 0.84·(1 − SSIM) + 0.16·L1 + 0.1·Gradient-L1, computed only on valid (non-no-data) pixels from v3 on. Its fully differentiable terms (weights in CONFIGS) complement each other:

  • (1 − SSIM) with an 11×11 Gaussian window (σ = 1.5) compares local mean, contrast and structure. It penalises the loss of local structure even when the average brightness is right, which directly targets blur on ridges and crater rims.
  • MSE / L1 anchors absolute brightness. SSIM is insensitive to uniform intensity offsets, so on its own it can drift in albedo.
  • Gradient L1 (finite-difference edges) penalises smeared or misplaced high-frequency edges, which helps sharp linear features such as ridgelines and scarps.

No perceptual loss is used, because every perceptual network we could use would be pretrained, and that is banned.

What the iterations taught us about this loss. Switching from MSE (v1) to this combination (v2) sharpened crater rims and scarps, but it did not recover dune-ripple texture: held-out SSIM only went from 0.705 to 0.707. The binding constraint is the bottleneck, not the loss. 256 floats for 51,529 pixels cannot store the exact phase of a ripple field, and a loss cannot recreate information the code has discarded. We keep the structural loss because it spends the unavoidable error on texture detail rather than on structure. Its edge sensitivity, however, made the network lock onto the razor-sharp edges of the no-data wedges (v2's novelty correlated 0.66 with the no-data share). That is why, from v3 on, every term is computed on valid pixels only (Section 0.2).

Phase 2 - Isolation Forest Novelty Engine

2.1 Novelty scoring

The Isolation Forest is fitted on the 1-D latent vectors of all crops (unsupervised: there is no "clean" training set). We use 500 trees and 256-sample sub-sampling (the original paper's recommended ψ), and average 5 forests with different seeds to reduce the variance of the ranking.

Score convention. sklearn's score_samples returns the negated anomaly score (higher = more normal). We negate it, so our Novelty Score = s(x, n) ∈ (0, 1] from Liu et al. (2008), and higher = more anomalous. This is the competition convention, and it is verified below by the sign of the correlation with sklearn's decision_function.

2.2 Statistical thresholding

We want the boundary to come from the shape of the observed score distribution, not from an assumed count. First we test whether a Gaussian μ + kσ rule is even appropriate (skewness, kurtosis, D'Agostino K² test, Q-Q plot). Then we compare three distribution-driven rules:

  1. Robust modified z-score (Iglewicz & Hoaglin 1993): M = 0.6745 (s − median) / MAD, flag M > 3.5. Median and MAD have a 50 % breakdown point, so the outliers being hunted cannot inflate the threshold. Under normality 0.6745 × MAD estimates σ, so 3.5 is comparable to ≈3.5σ.
  2. Kneedle elbow of the ascending sorted-score curve: min-max normalise both axes and take the point of maximum vertical distance below the chord joining the end points. This is the point of maximum curvature, where the curve turns from "bulk" to "tail".
  3. Two-component Gaussian mixture: the score where the posterior of the high-mean component exceeds 0.5.

  1. A Gaussian μ + kσ rule is not supported by the data. The v3 scores have skewness 0.96, excess kurtosis 0.98 and D'Agostino K² = 1,363 (p ≈ 0), and the Q-Q plot bends upward in the right tail. Worse, μ and σ are estimated including the tail we are trying to find, so the outliers inflate their own threshold. We keep μ + 3σ only as a cross-check.
  2. The elbow and GMM boundaries sit inside the body of the distribution, not at a break. After v3 removed the no-data mode, the score distribution is unimodal. A two-component GMM therefore splits the single skewed bulk into two overlapping Gaussians, and its boundary falls near the 71st percentile (2,986 crops). The Kneedle elbow of the whole sorted curve marks where the curve leaves its straight middle section, at the start of the ordinary right skew of normal terrain (1,513 crops). Neither boundary coincides with any change in the behaviour of the density.
  3. The modified z-score is built for exactly this situation. Median and MAD have a 50 % breakdown point, so however many outliers exist they cannot move the threshold. k = 3.5 is the value recommended by Iglewicz & Hoaglin (1993). If the bulk were Gaussian with this robust scale, only about 2 of 10,422 normal crops would exceed it by chance (printed below).
  4. Independent rules agree. The robust rule (86) and the classical μ + 3σ cross-check (95) land within 10 % of each other. On the sorted-score plot both sit at the foot of the final steep rise (the last ~100 points), where the curve turns from gradual to near-vertical. This is exactly the behaviour an elbow method should key on, once the elbow is sought in the tail rather than across the whole curve.
  5. Sensitivity is reported, not tuned. The printout shows how the count moves for k = 3 … 5. We keep the conventional k = 3.5 rather than choosing k to hit a count.

Final threshold = 0.5293 → 86 crops flagged

Contamination parameter

sklearn's IsolationForest(contamination=...) only changes the offset used by predict() to produce ±1 labels. It has no effect on score_samples(), which is all we use. We set contamination="auto" (sklearn's default, offset −0.5), and we never call predict(). The final anomaly count is determined solely by the statistical threshold on the continuous Novelty Score above, independently of any assumed contamination fraction.

2.3 Image location analysis

Each scored crop is joined to source_image_metadata.csv through its source_image_id (from crop_metadata_index.csv), many-to-one and validated. We then ask whether flags cluster in particular observations, latitudes, illumination conditions, seasons or resolutions.

Metadata resolution. The provided coordinates are quantised. Latitude is on a 5° grid from −45° to 60°, plus the two poles (±90°), and longitude takes only two values, 0° or 180°E (29 and 143 sources). A longitude-latitude map would collapse to two vertical lines, so we analyse latitude bands × the two longitudes instead of point locations. We test per-source enrichment with a one-sided binomial test against the global flag rate (Bonferroni-corrected), and test trends with rank statistics (Spearman, Kruskal-Wallis), which make no Gaussian assumption.

Findings.

  • Flags are spread over 39 of the 172 source observations, but 4 sources are significantly enriched (one-sided binomial test against the 0.83 % base rate, Bonferroni-corrected p < 0.05). The two strongest are both north-polar (90° N): SRC_039 has 13 of its 16 crops flagged and SRC_166 has 6 of 16. Together they contribute 19 of the 86 flags. The other two are SRC_067 (7 of 92, 15° S) and SRC_032 (3 of 14, 5° S).
  • Physical reading: rare terrain, not tampering. North-polar crops show bright ice, finely banded layered deposits and scarps. For example, the "stripes" of 08731 and 03423 are polar layering, not sensor banding. This terrain is a small minority of the training crops, so its latents are easy to isolate. A mission pipeline would route these flags to the polar science team rather than discard them. The metadata is what tells us these flags are a terrain class, not artefacts.
  • Latitude. Between 45° S and 55° N the flag rate fluctuates around the base rate (0-1.5 %), then jumps at 60° N (≈4.4 %) and 90° N (≈5 %). Correlation with |latitude| overall is negligible (ρ = 0.03), so the effect is confined to the high northern bands.
  • Illumination. ρ(sun angle, novelty) = −0.04. It is statistically significant only because n = 10,422; the effect size is negligible, and flagged crops span the whole 36-79° range.
  • Season. The score distributions differ slightly (Kruskal-Wallis p = 0.002), but flagging is independent of season (χ² p = 0.48).
  • Resolution. Scores differ strongly by resolution (p ≈ 10⁻¹¹), consistent with the t-SNE observation that pixel scale changes texture frequency. Yet the lone 1 m/px observation (SRC_111) has only 2 of 137 crops flagged, so scale shifts the bulk of the distribution but does not by itself produce flags.

We concatenate the standardised image latent with an encoded metadata vector: z-scored sun angle, sin/cos of latitude and longitude (to respect circularity), log₂ resolution, and a one-hot season. We re-score with the same Isolation Forest settings and the same modified-z rule, then compare the flagged sets. The image-only pipeline remains the primary result.

Fusion changes little: 93 crops are flagged against 86 image-only, with 83 in common (Jaccard 0.86) and a rank correlation of 0.992 between the two scorings. Fusion adds 10 crops and drops 3. Two reasons explain the small effect:

  1. The Isolation Forest picks split features uniformly at random, and only 10 of the 266 fused dimensions are metadata, so metadata drives about 4 % of splits.
  2. Every crop from one observation shares identical metadata. Metadata can therefore isolate an unusual observation, but never a single crop within it, whereas the injected anomalies are single crops.

Metadata is therefore most useful as we used it in 2.3, to explain flags after the fact (e.g. the polar enrichment), rather than as an input to detection.

3.2 Geological report

These are hypotheses, argued from the heatmap pattern, the descriptors (with percentiles against 500 normal crops) and the metadata. They are not definitive classifications.

#1 sample_00849 (SRC_022, 20° N): straight albedo boundary. Hypothesis: spliced terrain or a mosaic seam. A bright slope with gullies is cut by a straight, full-height boundary to a uniformly darker band (seam step 0.42, the 100th percentile; the crop is also brighter than every reference crop). Natural albedo contacts on Mars follow topography and are rarely ruler-straight across a whole frame. A straight contact between two unrelated surfaces is the signature of semantic splicing, or, less exotically, of a seam between two HiRISE CCD channels with mismatched gain. The reconstruction error is low (the decoder draws both halves and the boundary), so the flag comes from the rarity of the configuration in latent space, not from a failure to encode it. The only concentrated error sits on the edge of the small filled no-data wedge at the left, so part of this crop's score may be the residual no-data effect noted in the changelog.

#2 sample_06917 (SRC_122, 5° S): fresh crater filling the frame. Hypothesis: genuine, rare geology. The error forms a ring that follows the crater rim, with streaks down the inner walls. Its concentration is low (33rd percentile), spread along the whole rim. A sharp-rimmed impact crater with gullied walls, a shadowed wall and a bright floor is a high-relief, high-frequency structure that a 256-float global code can only sketch. Such large fresh craters are uncommon at this crop scale, where most crops are plains, dunes and knobby terrain. The pattern is physically coherent (the error sits exactly where relief is steepest) and does not resemble any of the injection signatures.

#3 sample_05849 (SRC_008, 25° N): crater or pit with a fully black shadow. Hypothesis: genuine steep-walled depression at the limit of the sensor's dynamic range. 11 % of the pixels are clipped at 0 (saturation at the 100th percentile). The error traces the rim and the sunlit wall, where the illuminated rock meets the clipped shadow. The shadow sits on the wall facing away from the sun, consistent with the illumination of the surrounding small craters, which argues for real topography rather than a synthetic black blob. An exposure set for the bright plain cannot record the shadowed interior, so it clips. This is either a very deep fresh crater or a collapse pit. It is rare, but Martian.

#4 sample_03423 (SRC_128, 90° N): polar layered terrain with a large filled no-data area. Hypothesis: genuine polar geology plus the residual no-data effect. The valid area is a rotated strip, with the two wedges masked and filled. It shows a bright, smooth upper surface and a darker lower surface separated by a curved scarp with fine parallel banding (periodicity at the 98th percentile). At 90° N this is the morphology of the north polar layered deposits, stacked ice and dust layers exposed on a scarp. The reconstruction error is the lowest of the top 5, so again the novelty is configurational: rare polar terrain, and an unusually large flat fill region, as discussed in the v3/v4 changelog.

#5 sample_03383 (SRC_067, 15° S): dark, low-sun rugged relief. Hypothesis: genuine massifs or ridges under oblique illumination. The frame is darker than 99 % of reference crops, and its contrast is at the 98th percentile. The error is concentrated on the thin sunlit crests, not in the shadows. Long shadows from steep spurs make a high-contrast, high-frequency pattern whose exact crest geometry the code cannot store. SRC_067 is one of the four significantly enriched sources (7 flags in 92 crops), which is what we would expect if the whole observation images unusual rugged terrain.

Beyond the top 5 (Fig 3.1b, diagnostic). The heatmap pattern separates the injected content from the rare geology above:

  • The Pentagon aerial photograph (rank 47) and the periodic grid (rank 11), which on close inspection resembles an orchard (rows of trees seen from above), have the two highest reconstruction errors in the whole dataset (100th percentile). Their error is spread diffusely over the entire frame (concentration 0.18 and 0.16, i.e. almost uniform). The decoder has no Martian vocabulary for rectilinear buildings or a perfect lattice, so it fails everywhere. This is the textbook non-Martian domain-shift signature.
  • The black bar and two streaks, which are not flagged by the latent score (ranks 1,120 and 2,211), nevertheless sit in the top 1 % of reconstruction error, with the error lying along the straight dark defect (line scores 4.6 and 5.4). This is the synthetic sensor-artefact signature, and it shows the global latent's blind spot for small local defects (changelog, v3 and v4).

v1 - Baseline: convolutional AE, pure MSE

Result. Held-out MSE 0.00189, SSIM 0.705 after 30 epochs (plateaued from epoch ~20).

Symptom 1 - Blurry reconstructions, fine texture erased

Dune ripple trains, small-crater fields and rough ground are reconstructed as smooth grey gradients (outputs/v1/recon_grid.png, random crops 07869 and 01503). The error maps of normal crops are dominated by texture, not by anything anomalous.

Symptom 2 - The novelty engine ranks map-projection borders, not anomalies

  • All of the top-25 Novelty Scores are crops with a black no-data wedge (the edge of the map-projected HiRISE strip). Their error maps are just a bright line tracing the wedge edge.
  • Spearman ρ(novelty, reconstruction MSE) = −0.095: what the forest isolates is unrelated to what the decoder fails to explain.
  • The score histogram has a long secondary shoulder (0.45-0.63) holding about 15 % of the crops, which is roughly the share of crops with a border. Even the robust modified-z rule (median + 3.5 MAD) therefore flags 1,596 crops (15.3 %), and the elbow and GMM rules flag even more. No defensible threshold can exist while a nuisance factor forms its own mode.
  • One latent coordinate has variance 2,800 against a median of 33, so the code spends its largest axis on border geometry.

Diagnosis

  1. Blur: MSE is minimised by the conditional mean. When the exact phase of a ripple or the rim of a small crater is uncertain, averaging the possibilities gives the lowest expected squared error. The decoder learns to hedge, which erases exactly the high-frequency geology we need in order to notice unfamiliar texture.
  2. Borders: a no-data wedge is a 0-valued region with a razor-sharp straight edge at an arbitrary angle and position. It is the highest-contrast structure in the dataset. Under MSE it dominates the loss, so the encoder dedicates capacity to encoding wedge geometry. In the latent space, crops with rare wedge angles are then the easiest points to isolate.

Fix

Addressed one at a time: v2 changes only the loss (symptom 1); v3 addresses the no-data nuisance (symptom 2).

v2 - Structural loss: 0.84·(1 − SSIM) + 0.16·L1 + 0.1·Gradient-L1

Change (loss only; architecture, data and schedule identical to v1).

  • SSIM (11×11 Gaussian window) penalises lost local contrast and structure even when mean brightness is right, which directly targets blur. The 0.84 / 0.16 split follows Zhao et al. (2017, Loss Functions for Image Restoration with Neural Networks).
  • L1 replaces MSE as the intensity anchor. SSIM ignores uniform offsets, and L1 is less dominated by a few huge errors than MSE.
  • Gradient-L1 on finite differences penalises smeared ridgelines and crater rims.

Symptom 1 (blur) - essentially unchanged

Crater rims are slightly crisper, but dune ripples (crop 01503) and small-crater fields are still reconstructed as smooth gradients, and held-out SSIM moved by only +0.001.

Diagnosis. The loss was not the binding constraint. The code has only 256 floats for 51,529 pixels (≈200× compression), squeezed through a single linear layer from an 8×8×256 map. The exact phase of a ripple field is high-entropy information that such a code cannot store. Whatever the loss, the decoder can only output the "texture class" with its details averaged out. Lesson: the loss decides how the unavoidable error is distributed; it cannot create information the bottleneck discarded. For anomaly detection this matters less than it first seemed. The latent only has to encode what kind of terrain a crop is, which it can do without reproducing every ripple.

Symptom 2 (no-data borders) - got worse

The novelty histogram (outputs/v2/scores.png) is now clearly bimodal. The second mode (0.47-0.60) is almost entirely crops with a black no-data wedge. ρ(novelty, no-data fraction), already 0.63 under v1, rose to 0.66. The number flagged grew from 1,596 to 1,985, and every crop in the top 25 has a wedge.

Diagnosis. Both new loss terms are edge-sensitive. The wedge boundary is a 0 → bright step, the strongest gradient in the dataset, so SSIM and gradient-L1 reward the network for placing it exactly. The encoder therefore spends more of its (already scarce) capacity on wedge angle and position (the latent spectrum became more concentrated, 44 → 36 PCA components). In latent space, crops with unusual wedge geometry are the easiest to isolate. The wedge is an artefact of map-projecting the HiRISE strip, not terrain, so every one of those flags is a false positive by construction.

Fix → v3

Stop showing the network the wedge. Detect no-data regions, fill them with the crop's median, and exclude them from the loss and error maps, keeping the v2 loss.

v3 - No-data masking (data/loss change; architecture and loss weights as v2)

Change. A no-data mask per crop marks near-black (≤ 5) regions that survive a 5×5 opening, touch the crop border and cover at least 0.5 % of it, dilated by 2 px for JPEG ringing. The opening matters: thin interior dark lines, which could themselves be sensor-glitch anomalies, are deliberately not masked (outputs/nodata_check.png). Masked pixels are filled with the crop's valid-pixel median and excluded from every loss term, metric and error map. 19.7 % of crops have a mask, covering 18.8 % of those crops on average.

Symptom - small local glitches are ranked far below the threshold

During the sanity pass we noticed crops with obvious synthetic defects: a thick black bar (00015), two black streaks (00503) and square dead-pixel blocks (00676). These are qualitative spot checks we saw by eye; we used them only to diagnose, never to tune the threshold. v3 ranks them 1,120th, 2,211th and 304th, far below the 86 flagged, even though their reconstruction error is visibly concentrated on the defect. A secondary residual: 41 of the 86 flagged crops still have a (filled) wedge, against a 20 % base rate. A large perfectly flat region is itself uncommon.

Diagnosis

The bottleneck is one global linear layer from the whole 8×8×256 feature map to 256 numbers, and that layer is trained to summarise normal terrain. A defect covering about 2 % of the pixels barely moves this global summary: the encoder projects the crop onto the normal-terrain manifold and "forgets" the bar. The decoder then reproduces clean terrain, which is why the defect shows up in the residual but not in the latent. Latent-density detection with a global code is sensitive to scene-level novelty (Earth imagery, alien textures) and blind to local defects (glitches, splice seams).

Fix → v4

Keep the information local. Replace the global linear bottleneck with a spatial bottleneck, a 1×1 convolution to an 8×8 grid of 4 channels, flattened to the same 256-d 1-D vector. Each coordinate then describes one ~63 px neighbourhood, so a local defect drives a few coordinates to extreme values, which is exactly what an Isolation Forest's axis-aligned random splits isolate fastest.

v4 - Spatial bottleneck (architecture change; loss and masking as v3) - REJECTED

Change. The encoder's 8×8×256 map is reduced by a 1×1 convolution to 8×8×4 and flattened to a 256-d 1-D latent. The latent size, compression ratio, loss, masking and schedule are all as in v3. Dropping the two 16,384×256 linear layers cuts the model from 11.1 M to 2.7 M parameters.

Symptom

The local glitches did not move up; they moved down. The content anomalies that v3 caught (the Pentagon, the periodic grids) were pushed out of the flagged set, and the flagged set grew six-fold. It is now almost entirely very dark or very bright scenes (outputs/v4_flagged_grid.png), which is exactly the "brightness heuristic" failure the organisers warned about.

Diagnosis

With only 4 channels per cell and no mixing across cells, each coordinate becomes a local albedo / local gradient descriptor. An Isolation Forest isolates points that are extreme along individual coordinates, and in a code made of local-albedo features the most extreme crops are simply the darkest and brightest scenes. The injected defects are anomalous in their configuration (a perfectly straight dark bar, square blocks, a regular grid), not in their local brightness. At the scale of a 63 px cell, a black bar is about as dark as an ordinary shadow, so none of its coordinates is extreme. The global code of v3 can represent "this scene contains an unnatural structure", because its linear layer combines evidence across the whole crop. The per-cell code cannot.

Decision

Revert to v3 as the final model. v4 stays in the journal as a documented negative result. The choice is made on label-free evidence: v3's novelty agrees better with what the decoder fails to explain (ρ 0.44 vs 0.22), it depends much less on raw brightness, and its score distribution gives a small tail on which the robust and Gaussian rules agree (86 vs 95). The spot checks only corroborate this.

Remaining limitation (honest). Recall is incomplete. A second Earth image (an aerial view of buildings, crop 05508, spotted in v4's grid) ranks 354th under v3 and is not flagged. Small local defects are still missed by latent-space scoring in every version. The decoder residual catches two of the three: the black bar and the two streaks are in the top 1 % of reconstruction error, with their error lying along the defect (Fig 3.1b). The dead-pixel blocks are invisible even there (53rd percentile). Residual-based or patch-level scoring is therefore a promising extension, but not a complete answer. v3 also keeps some brightness bias: 58 % of its flags lie in the brightness extremes, against a 10 % base rate. Some of that is genuine, because unusually bright or dark terrain (frost, deep shadow) is rarer.
